## [Unreleased]

### Added
- M1 Phase 3 chunk 1 (engine port, no chrome yet): the flipbook engine moves from the spike to `src/features/reader/engine/` as `FlipbookEngine.create(canvas, { pages, scene, startSpread, reducedMotion, onChange, onError, onGeometry }, signal?)`. It rejects without WebGL2 and decodes page 1 first to fix the page box. The controller has `next()`, `prev()`, `goTo(spread)`, `setScene(scene)`, and `dispose()`. `onChange` fires `{ spread, spreads, turning, loaded }` on discrete changes only. The window `keydown` listener is gone: the engine owns canvas pointer input only (drag, cancel, lost-capture, and queued navigation are unchanged). New modules: `spreads.ts` (`spreadOfPage`, `firstPageOfSpread`, `pagesOfSpread`, `spreadCount`), `turnMachine.ts` (turn state and the nav queue, GL-free), `lruCache.ts` and `pageTextures.ts` (the LRU and page cache over a `TextureBackend`, so tests use a fake), `decode.ts` (`PageDecoder` seam for chunk 2's worker), `renderer.ts`, `pointerInput.ts`, `camera.ts`, `corners.ts`. `setScene` rebuilds the paper texture and drops every cached page. `webglcontextlost` stops the loop and drops textures, and `webglcontextrestored` rebuilds programs and reloads the open spread. Every texture upload, including the paper one, checks `gl.getError()`, and a failed page shows paper and calls `onError`. Reduced motion replaces the curl with a 0.2 s cross-fade (no peek, no drag; a tap turns). `onGeometry` receives a preallocated 3x9 `Float32Array` of projected page corners in canvas pixels while a leaf moves and once on settle (layout in `corners.ts`). `goTo` during a turn now waits for the turn instead of being dropped. The daylight scene moved to `design/skins/daylight/scene.json`. The dev `#spike` route now renders `features/reader/DevHarness` (last book, lamplit scene, Prev/Next/Scene/Remount/Reduced motion); the old spike files stay until chunk 5. Vitest coverage now includes the pure engine modules (GL, shader, and pointer files are excluded).
- M1 Phase 3 chunk 0 (progress-save follow-ups from the PR #66 review): the per-turn sleeper thread is gone. One worker per dirty book (`Session::claim_worker` hands out a token; `worker_step` waits, writes, and releases under the session lock) sleeps to the 1 s due time, retries at the 10 s backoff after a failure with no page turn, and exits when the book is clean or its token is superseded. Inline writes, `close_book` and the exit flush never clear its claim. A background success emits `progress-saved` `{ root }` (`onProgressSaved` in `api.ts`), and `BookView` clears its warning and settles the save-result gate. **Close book** now awaits `close_book`: on failure the reader stays open with the warning. `create_book` takes an `importId`, echoed in every `ingest-progress` `{ importId, done, total }`; `onIngestProgress(importId, cb)` ignores other imports' ticks. New helpers without an `AppHandle`: `register_in_session`, `claim_after_save`, `run_worker`, with tests.
- PR #66 review fixes: the asset scope admits exactly the page files `load_book` verified (no static scope, no directory grant). `save_progress` takes a `seq`, and Rust ignores a save older than one it has, so a late save never overwrites a newer page. Each opened view carries the book's highest number, so a reloaded webview keeps saving. A held page is written about a second later (one delayed flush per book) and on **Close book** (`close_book`), so a crash while reading loses at most the last second. The import form ignores a second submit. A book built but unopenable is removed so a retry is not blocked. `inspect_folder` and `suggest_book_id` report read errors instead of guessing. The import form checks text limits up front, and a failed progress listener no longer blocks the import.
- M1 Phase 2 chunk 6 (docs): `docs/manual-test-m1.md` is the manual script for Phase 2. It covers setup, create and open, paging (A5), reopen without a copy (A7), progress across restarts and the Rust close flush (A6), error dialogs, keyboard and focus, the `pnpm tauri build` production-CSP gate (A13), and how to reach the dev-only spike at `#spike`. It leaves an empty Results table for the tester. README gains a short Try it section, and `docs/NAVIGATION.md` links the script. The plan ticks chunks 0–4 and 6. Chunk 5 stays open for its release-build gate, and running the manual script is the only remaining item.
- M1 Phase 2 chunk 5 (UI): the app is now the real reader. `App.tsx` calls `lastBook()` on start (loading state, then the saved page or Home) and shows the flipbook spike only in dev builds at `#spike` (a dynamic import behind `import.meta.env.DEV`, so the release bundle has no spike code). New `src/features/`: `home/Home` (Open… then `inspectFolder`, `openBook` or the confirm dialog), `home/ConfirmIngest` (counts, MB estimate, editable title, id with live `isValidBookId` hint, optional rights and attribution, `<progress>` fed by `onIngestProgress`, no cancel while ingesting), `common/Modal` (native `<dialog>` with `showModal`; Escape closes unless ingest runs) and `common/ErrorDialog` (every rejected call), `book/BookView` (title, Close book, `n / total`, Prev/Next, arrow keys via `stepPage`, `<img>` with `object-fit: contain`, `saveProgress` on each page change). Plain CSS per feature. New pure helpers with tests: `lib/format.ts` (`formatMegabytes`, `pageLabel`, `pageAlt`, `progressLabel`), `lib/dom.ts` (`isTypingTarget`), `bookIdHint` in `lib/bookId.ts`. Components have no automated tests and need a manual click-through.
- M1 Phase 2 chunk 4 (TypeScript helpers only, no UI yet): `src/lib/bookTypes.ts` (types matching the Rust JSON: `FolderInfo` tagged on `kind`, `BookView`, `PageView`, `IngestProgress`, `CommandError`); `api.ts` (typed `invoke` wrappers for the five commands, `onIngestProgress`, `pickFolder`, `pageUrl`; every rejection goes through `toCommandError`); `errors.ts` (`errorHeading` for every `BookError` variant plus `Internal`, `isCommandError`, `toCommandError`); `bookId.ts` (`isValidBookId`, mirroring `validate_book_id`, tested against the Rust accepted and rejected ids); `paging.ts` (`stepPage` for the arrow keys). `src/lib` coverage is 100% lines.

### Changed
- CI guide: CodeQL is the existing branch-ruleset code-scanning requirement (GitHub default setup), not an M0.5 follow-up. A `Vulnerabilities found` pnpm result is a per-dependency lockfile or `package.json` update, not an automatic package bump.
- **Dependency audit** no longer dies on npm infrastructure: `pnpm audit --prod` (both `ci.yml` and the weekly `security.yml`) now runs through `ci/scripts/pnpm-audit.sh`. The pnpm version is the top-level `package.json` `packageManager` field, read as JSON so compact and multiline manifests both work. `corepack prepare` retries only registry-shaped output (default 3 attempts, capped at 5); a permanent prepare failure is `pnpm setup failed` and is not retried. `pnpm audit` output retries the same registry shapes (`error (503)`, `error (23)`, `TimeoutError`, `HTTP 503`, and pnpm 11's `ERR_PNPM_AUDIT_BAD_RESPONSE` text `responded with 5xx`). `corepack enable` is not retried. Exhausted registry retries fail closed with `Audit did not run`; a broken toolchain reports `Audit tooling unavailable`; a missing `pnpm` exits 127. A non-transient failure with no registry error reports `pnpm audit failed`. A report containing `vulnerabilities found` exits immediately with pnpm's status, even if it also mentions a 503. `PNPM_AUDIT_ATTEMPTS` and `PNPM_AUDIT_DELAY` accept integers of at most 3 digits. Contract tests: `tests/test_pnpm_audit.py`. Motivation: on 2026-10-22 four runs went red on 503s and client timeouts with no vulnerability present. CI shellcheck now uses one `scandir` step per directory (`find "$INPUT_SCANDIR"` is a single path; the old space-separated value matched nothing and still exited 0).
- Dependabot: replaced the semver-major `ignore` rules with `allow` (minor/patch) so version updates still skip majors but security updates that need a major are no longer suppressed; removed the `docker` entry (no Dockerfile in the repo).
